场景优先级

用于决定首次产品扫描投入顺序。默认综合 AI 优势、AI Revenue TAM、需求频次、创业热度，并用 TAM 可信度修正。
评分权重与分层规则
属于方法配置，默认折叠；需要调整时再展开。
权重可编辑，系统自动归一化；TAM 可信度作为乘数修正，不单独占权重。
各维度 1–5 分规则
AI优势：5=AI-native，核心价值依赖生成/推理/多模态/Memory/Agent执行，传统产品难以完成；4=AI带来明显质变，但传统工具/人工仍有可用替代；3=AI有帮助，但搜索、Marketplace、规则工具已能解决大部分需求；2=主要是便利性/推荐增强，AI并非必要；1=几乎没有独立AI价值。
需求频次：5=周频及以上；4=月2–4次；3=月度/季度；2=年1–3次；1=低于年1次。
创业热度：默认自动计算，来自Product Hunt / YC / GitHub / 跨渠道覆盖 / a16z&CBI等外部验证；不是主观硬填。
AI Revenue TAM：不手工打分，按当前场景TAM做平方根归一化到1–5附近，并乘TAM可信度(A=1.0/B=0.9/C=0.75)。
完整链路潜力：按AI任务覆盖数量：1类=1分、2类=2、3类=3、4–5类=4、≥6类=5。
创业热度配置
关闭后=手动模式，下方“创业热度”列可直接编辑PH %YC %GitHub %跨渠道 %外部验证 %
阈值：2分≥3分≥4分≥5分≥
例如 S=20、A=50 表示：S 为 Top 20%，A 为 20%–50%，B 为其余。可随时调整。

发现型渠道

验证型渠道
a16z / CB Insights
目标是验证用户规模、资本投入、商业化和市场动量，不机械追新品。
入库原则
渠道里发现 ≠ 自动进入产品池。只有满足 2C相关 / AI-native / 新Pattern / 有验证信号 / 对通用AI有启发 中至少两项，才进入正式研究池。
渠道抓取入口扫描范围扫描方法状态本轮结果后续动作
榜单自身入围机制 & 我们的入库规则
区分“平台怎么排榜”和“我们什么情况下收入研究池”，避免把二者混为一谈。
Product Hunt · Week / Month
平台机制：Day/Week/Month本质按“points”排名；points不等同于裸upvotes，而综合真实upvote与有意义互动（如评论/分享），并做真实性与反作弊处理。官方不公开完整算法。Week比较周一至周日launch，Month比较自然月launch。
我们的入库：Monthly完整浏览显式排名；Weekly做增量。优先收入 Rank靠前、Reviews/讨论真实、出现新Pattern、且对2C/通用AI有启发的产品。
GitHub Trending · Today / Week / Month
平台机制：GitHub官方只表述为“社区当前最兴奋的项目”，支持Today / This week / This month，并展示对应周期新增stars；官方没有公开精确Trending算法。
我们的入库：重点看周期新增stars、增长速度、持续上榜、最近commit与产品化程度；过滤模型权重、教程、纯infra。只有出现消费级Agent / Memory / Skills / 新交互Pattern，或异常增长，才进正式产品池。
